# Data model

All schemas are JSON Schema draft 2020-12, generated by `scripts/make-schemas.mjs` into `schemas/`. They set `additionalProperties: false`, and state enums are taken from `status-machines/`. Status: **implemented, tested.**

| Schema | Object | ID prefix (reference) | Notes |
|---|---|---|---|
| `common` | Shared definitions | | Digests, timestamps, IDs, zoned slot, actor, signature |
| `matter-participant` | Participant | | consumer, firm, observer, with role and access |
| `legal-matter` | Matter | `mat_` | Machine `matter`; carries the CaseBrief revision; the CaseBrief is encrypted at rest |
| `disclosure-grant` | Grant | `grt_` | Bound by `grant_digest`; `use` is `one_time` or `bounded_class` |
| `approval` | Approval | `apv_` | Preview of exactly what is shared; never contains the code |
| `conflict-screen` | Conflict screen | `scr_` | Machine `intake` |
| `consultation` | Consultation | `cns_` | Machine `consultation`; slots carry an IANA zone and a UTC instant |
| `engagement` | Engagement | `eng_` | Machine `engagement`; the offer is versioned and bound to document SHA-256s |
| `conversation-thread` | Thread | `thr_` | Members, observer access, closed flag |
| `message` | Message | `msg_` | Machine `message_delivery`; full form or observer status-only form |
| `document-reference` | Document | `doc_` | SHA-256, sanitized name, sniffed type, scan result |
| `lifecycle-event` | Event | URN | The envelope from spec section 10 |
| `audit-record` | Journal entry | | `seq`, `recorded_at`, `prev_hash`, `entry_hash` |
| `delivery-receipt` | Receipt | | Signed by the recipient endpoint |
| `matter-passport` | Passport | | Host-signed export; authorizes nobody |
| `capabilities` | Capabilities | | Profiles, topology, `paid_influence: false`, mode |
| `error` | Error | | `{olip_version, error:{code, message, retryable, details?}}` |
| `state-machine` | Machine file | | Validates `status-machines/*.json` |

## Relationships

```
matter 1─* participant
matter 1─* conflict_screen (one per organization)  ─► gates CaseBrief disclosure to that organization
matter 1─* consultation   (per organization)
matter 1─* engagement     (per organization; at most one firm_confirmed)
matter 1─* thread 1─* message 1─* document
matter 1─1 journal (hash chain of every event)
grant  *─1 matter, 1 recipient, 1 action, 1 purpose; approval 1─1 grant
```

## Revisions

Every lifecycle object has an integer `revision`. Every firm event names `prior_revision`, which must equal the current revision. A matching event advances the revision by one. Two valid events at the same revision with different outcomes create a reconciliation record.

## Examples

`examples/valid/` holds 17 examples taken from a real fictional Scenario A run. `examples/invalid/` holds 15 examples, each breaking one rule. `examples/index.json` maps each example to its schema and expected result. Status: **tested** (`tests/schemas.test.mjs`).

## Data that is never stored or returned

- Approval codes (only a SHA-256 hash of the code is stored).
- Tokens in logs.
- Message bodies or CaseBriefs in plaintext at rest.
- Real personal data. Everything in this package is fictional.
