# OLIP 2.0-draft: the legal-client lifecycle (proposed)

> OLIP 2.0 is a proposed extension of the Open Legal Intake Protocol that introduces interoperable consultation, firm-controlled engagement events and secure ongoing communications. It is under development, has not been adopted by any standards body, and has not been approved by a bar or regulator. The published OLIP 1.0 release remains unchanged and separately available.

Everything in this folder is **fictional test data** and **mock mode only**. Nothing here is deployed. Nothing here sends real mail, calendar invites, payments or messages.

## What it does

OLIP 1.0 ends when a consumer's approved handoff reaches a lawyer. 2.0-draft adds five optional, negotiated profiles that continue from there, each with its own state machine:

| Profile | Stage | Who decides |
|---|---|---|
| `olip-lifecycle-core/2` | Conflict-aware intake: minimal screening first, the fuller CaseBrief only after the firm says intake may continue | The **user** approves every disclosure; the **firm** decides whether intake continues |
| `olip-consultation/2` | Consultation request, firm-offered times (IANA zone + UTC), firm confirmation, firm-attested attendance | The **firm** confirms times and reports attendance (with a named source) |
| `olip-engagement/2` | Versioned engagement offer bound to document SHA-256s, user accept/decline of one exact version, firm confirmation | Only the **firm's authorized attorney** can sign `firm_confirmed` |
| `olip-communications/2` | Threads, messages and documents with truthful delivery and read states | The **user** approves each substantive message; only the recipient's signed receipt counts as delivery |
| `olip-matter/2` | Inactive, closure, termination; a signed, portable matter passport | The **firm** closes a represented matter; the **user** exports their passport |

An assistant (through the API, MCP or A2A) can prepare everything and approve nothing. There is no approve, confirm or accept operation for agents anywhere.

## Layout

| Path | What |
|---|---|
| `spec/OLIP-2.0-DRAFT.md` | Readable draft normative text |
| `status-machines/` | The five machines and cross-machine invariants (generated by `scripts/make-machines.mjs`) |
| `schemas/` | 18 JSON Schemas (draft 2020-12), generated by `scripts/make-schemas.mjs` |
| `openapi/olip-v2-draft.json` | OpenAPI 3.1, generated from the reference host's route table (55 operations) |
| `examples/` | 17 valid and 15 invalid fictional examples, taken from a real run |
| `vectors/golden-vectors.json` | Canonical JSON, digests, Ed25519 signatures, grant digest, journal chain, time zones, webhooks |
| `reference/` | Vendor-neutral lifecycle host, firm-owned endpoint, both topologies, 1.0 + 2.0 combined host, demo |
| `adapters/mcp/` | MCP adapter on the official MCP TypeScript SDK (pinned 1.32.2) |
| `adapters/a2a/` | A2A 1.0 adapter on the official A2A JavaScript SDK (pinned 1.3.0) |
| `sdk/typescript/` | Typed client with signature, webhook and status helpers |
| `sdk/python/` | Separate standard-library Python client and verifier |
| `conformance/` | Black-box runner (pass / fail / skip / mock-only) and results |
| `tests/` | 97 tests: security, consent, firm authority, lifecycle, compatibility, property, contract |
| `docs/` | Architecture decision record, audit, security, policy, UX, integration, conformance matrix, test report, release gates, progress, migration, risks |

## Commands

```bash
cd protocol/v2-draft
npm ci
npm test            # builds the TypeScript client, then runs all 2.0-draft tests
npm run demo        # Scenario A, discovery to closure, in both topologies (fictional)
npm run conformance # black-box runner against the reference host in four configurations
npm start           # local fictional system: lifecycle host, firm endpoints, combined 1.0 + 2.0 address
```

Regenerate the derived files (tests fail if the committed copies drift): `node scripts/make-machines.mjs`, `node scripts/make-schemas.mjs`, `node scripts/make-openapi.mjs`, `node scripts/make-examples.mjs`, `node scripts/make-vectors.mjs`.

## Neutrality

No part of this folder needs ESQ CoPilot, EsqHarness, the sponsor's servers, a paid account, lead fees, referral fees or paid ranking. Discovery stays alphabetical with `paid_influence: false`. Any firm or vendor can run the host or the firm endpoint.
