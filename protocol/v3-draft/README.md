# OLIP 3.0-draft: agent compatibility layer (proposed)

> OLIP 3.0 is a proposed draft under development. It is not a stable release, has not been adopted by any standards body, has not been independently security reviewed, and has not been approved by any bar or regulator. OLIP 1.0 and the 2.0 draft are unchanged.

Everything in this folder is **fictional test data** and **mock mode only**. Nothing here is deployed. Nothing here contacts a real person, firm or service.

## What it does

OLIP 2.0-draft defines the steps between a person and a law firm after intake. 3.0-draft lets an **existing AI application** use those steps safely with little custom code. It works with MCP and A2A, and with plain HTTPS.

| Part | What an assistant gets | Who decides |
|---|---|---|
| Signed agent manifest | One catalog of 22 actions: effect, who may call, what approval is needed | Documentation only; the gateway decides |
| Policy gateway | One decision for every call, from server-side state only; unknown or unreviewed jurisdictions fail closed | The host's policy, set by the operator |
| Approval-bound disclosure | Prepare, the user approves on the host's page, send exactly that, once | The **user**, on the approval page |
| Durable workflow and signed journal | A stable workflow id, hash-chained signed events, cursors with gap detection, optional webhook hints | Firm facts come only from firm-signed 2.0 events |
| Legal context capsule | A selective, signed, optionally encrypted export the user can hand to a second assistant | The **user** exports and authorizes each import |
| Next-actions planner | Deterministic next steps with dispositions and reasons | Never permission; rechecked when called |

An assistant can prepare everything and approve nothing. No action, MCP tool or A2A skill approves, accepts or confirms.

## Layout

| Path | What |
|---|---|
| `spec/OLIP-3.0-DRAFT.md` | Readable draft normative text |
| `schemas/` | 24 response and document schemas plus 22 action input schemas (JSON Schema 2020-12), generated by `scripts/make-schemas.mjs` |
| `openapi/olip-v3-draft.json` | OpenAPI 3.1, generated from the route table (24 routes plus 4 static documents) |
| `examples/` | 21 valid and 14 invalid fictional examples, captured from a real run |
| `vectors/v3-vectors.json` | Canonical JSON, journal chain, capsule digest and signature, sealed capsule, webhook, plan digest |
| `policy/policy-set.json` | Illustrative jurisdiction policy: every entry is pending counsel review |
| `reference/` | Agent layer (gateway, journal, capsules, planner, webhooks), HTTPS binding, store, demo, sandbox |
| `adapters/mcp/` | MCP adapter on the official MCP TypeScript SDK (pinned 1.32.2), in-memory and stdio |
| `adapters/a2a/` | A2A 1.0 adapter on the official A2A JavaScript SDK (pinned 1.3.0) |
| `sdk/typescript/` | Client with manifest, journal, webhook and sealed-capsule verification (fetch and WebCrypto only) |
| `sdk/python/` | Separate Python client and verifier; vector and live checks |
| `conformance/` | Black-box runner (pass / fail / skip / mock-only) and results |
| `tests/` | 70 tests: contract, policy, consent, firm authority, tenancy, capsules, journal, webhooks, planner, MCP, A2A, bindings, Python, compatibility, end to end |
| `docs/` | Audit, architecture and decisions, quickstart, compatibility, errors, risks, gates, progress, test report, migration, final report |

## Commands

```bash
cd protocol/v3-draft
npm ci && (cd ../v2-draft && npm ci)
npm test            # builds the TypeScript clients, then runs all 3.0-draft tests
npm run demo        # the 12-step fictional journey with two assistants
npm run conformance # black-box runner against a mock build and a production build
npm start           # local fictional sandbox; prints an address and a fictional assistant token
```

Regenerate derived files (tests fail if the committed copies drift): `npm run generate`.

## Neutrality

Nothing here needs the sponsor's products, servers, accounts or paid services, and nothing pays for inclusion or order. Discovery stays alphabetical with `paid_influence: false`. Any firm or vendor can run every part.
